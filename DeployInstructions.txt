Prerequisites
-------------
Docker 23+ / BuildKit (buildx) is required.


Build & push
------------
./build.sh

IMPORTANT: pushing commits to git does NOT change the deployed app by
itself. The version shown in the footer/about page (and now in `docker
logs`, see Verify below) only changes when ./build.sh runs — it computes
APP_VERSION from the current commit count and bakes it into a fresh image,
then pushes that image to Docker Hub. If you skip this step and go
straight to the EC2 deploy below, `docker pull` just re-pulls whatever
image was already tagged `:latest` — same version, same code, no-op.

build.sh supplies the maintainer's build context from ../TaintedPort-Vulns
via '--build-context vulns=...'. Without that context the image ships the
in-repo stub from vulns-stub/.

(Or manually — pass the build-context, or you ship the stub:)

docker buildx build --platform linux/amd64 \
    --build-context vulns=../TaintedPort-Vulns \
    -t nunoloureiro/taintedport:latest .
docker push nunoloureiro/taintedport:latest


Deploy on EC2
-------------
sudo docker pull nunoloureiro/taintedport:latest
sudo docker stop taintedport; sudo docker rm taintedport
sudo docker run -d \
    --name taintedport \
    --restart unless-stopped \
    -p 127.0.0.1:8080:80 \
    -e ADMIN_USER='<username>' \
    -e ADMIN_PASS='<strong-password>' \
    nunoloureiro/taintedport:latest

REQUIRED: ADMIN_USER / ADMIN_PASS secure the restricted /a area. If you
omit them the image falls back to built-in development defaults that are
NOT safe for a public deployment. Always set your own values here.


Verify
------
sudo docker logs --tail=30 taintedport
# Expect: "  Version: 1.<commit count>" near the top (confirms this is the
# image ./build.sh most recently produced, not a stale pull) and
# "[init] php-fpm socket present at /var/run/php-fpm.sock"

curl -sI -H 'Host: api.taintedport.com' http://localhost:8080/wines | head -1
# Expect: HTTP/1.1 200 OK
